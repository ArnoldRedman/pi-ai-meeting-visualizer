## 多个模型一起开会，你只看得到最后那段结论

我给它做了间能看见过程的本地 3D 会议室。先说清楚免得你往下看才发现：**`pi-ai-meeting-visualizer`，我自己写的开源插件**，代码在 <https://github.com/ArnoldRedman/pi-ai-meeting-visualizer>。

### 你看不到的那些中间状态

我平时习惯让几个模型同时回答同一个问题，Claude 一份、GPT 一份、DeepSeek 一份，摊开比。真正难受的不是等，是等的时候什么都看不见——谁还在写、谁已经交卷、谁讲着讲着改了立场，在终端里全都化成一串「运行中」。

而多模型开会这套机制本身是完整的：几个模型并行独立表态，第二轮匿名交叉质询，最后投票定案（这部分是另一个开源项目 [pi-ai-meeting](https://github.com/ArnoldRedman/pi-ai-meeting) 在做）。问题是**会议的过程和结论一样有信息量，却只有结论能被人看到**。

所以我给它做了间屋子：每个模型是桌边一个人，谁在干活、谁先交卷、最后结论写在哪，一眼看到。

![一个人还在干活，另外三个已经交卷离桌去溜达了](https://raw.githubusercontent.com/ArnoldRedman/pi-ai-meeting-visualizer/main/assets/screenshots/mixed-state.png)

### 房间里有什么

总共做了 8 个厂家角色：GPT、Claude、Gemini、Grok、DeepSeek、Kimi、GLM、Qwen（都是自己照各家风格画的 chibi，不是拿现成模型换皮）。插件按席位模型名里的厂家关键词自动挑角色；碰到还没做角色的厂家（比如 Mistral）就用默认小人顶替——会议照开，不会因为缺角色中断。

![六个席位同框：五个厂家角色 + 一个认不出的厂家用默认角色](https://raw.githubusercontent.com/ArnoldRedman/pi-ai-meeting-visualizer/main/assets/screenshots/meeting-overview.png)

### 一场会议在房间里怎么发生

- 会议开始，角色走到自己座位坐下；
- 干活的席位留在电脑前，气泡写它公开出来的进度；
- **提前交卷的席位会离开桌子去溜达**：看窗外、翻书柜、浇绿植、窝沙发，等其他人；
- 全员完成后回座，一起转向墙上的大屏幕，那上面写这一轮到哪了、最终结论是什么；
- 点某个人，镜头拉近，看它的公开档案：职责、立场变化、按轮次记录的结论。

![点开一个席位：公开档案、立场变化和本轮结论](https://raw.githubusercontent.com/ArnoldRedman/pi-ai-meeting-visualizer/main/assets/screenshots/seat-focus.png)

没有专属角色的厂家就用默认角色：

![认不出的厂家（Mistral Large）用默认角色顶替](https://raw.githubusercontent.com/ArnoldRedman/pi-ai-meeting-visualizer/main/assets/screenshots/character-fallback.png)

### 接上真实会议是什么样

装好之后不需要多一个步骤：你用 pi-ai-meeting 开会，Pi 开始跑会议脚本的那一秒，房间自己建好了，Pi 里会给你一条门牌链接。之后在你面前发生的是：

- 四个席位一起坐下开工（真开会时它们确实是并行的）；
- **谁先答完谁先离桌**，它的结论直接挂在它的档案里，你立刻能看，不用等整轮；
- 交叉质询里改了立场的席位，档案里的立场会跟着变，两次的说法都留着；
- 全员收口，大屏幕上写最终结论和票型。

这也是我做这个东西的全部理由：同一场会议，之前我拿到的是「等了八分钟，得到四段结论」；现在中间那八分钟是有形状的。

### 它刻意不做什么（这段比上面重要）

- **它看不到模型的思考过程**，这是设计选择不是缺陷。插件只接收会议脚本愿意公开的事件：进度和立场。席位内部怎么推理的，它拿不到也不去读。所以你会看到「它改口了」，看不到「它为什么改口」——真要写「看见模型在想什么」，这项目就不成立了。
- **它不碰会议本身**：表态、质询、投票、谁赢，都是 pi-ai-meeting 算的，插件只负责画。
- **全程本地**：服务只绑 `127.0.0.1`，数据只在内存，Pi 一退服务就停。没有账号、没有云、没有上传。

代价说清楚：会议结果要等整轮跑完才落盘，所以最细的粒度是「谁先答完谁先出结论」，不是逐字直播。

### 怎么用上

需要 Node 22+ 和一个 Pi（跑在终端里的 coding agent）。

```sh
pi install git:github.com/ArnoldRedman/pi-ai-meeting-visualizer
# 装完重开一个 Pi 会话（或 /reload）让扩展生效，然后：
# /meeting open
```

`/meeting open` 会起本地服务并打开页面，页面上点「开始模拟会议」就能看一场内置演示——不调用模型，先确认画面正常，半分钟看完一轮。真正开会需要装 pi-ai-meeting：开会时房间会自动出现，Pi 里会给你一条门牌链接，点开就是这场会（默认不自动弹浏览器，也不会擅自关服务，都可以用 `/meeting config` 改）。

不装 Pi 的话，这篇文章对你就是几张图——这是我得承认的门槛。想先判断值不值得看，装完 `/meeting open` 点一下模拟会议：里面的人会走开、会回来、屏幕上会出现结论。等你自己开一场真的多模型会议，就能看到那些原本「不存在」的中间状态原来长这样。
